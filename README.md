# NS每日签到

独立的 MoviePilot V3 插件，插件 ID 为 `NodeSeekSignCustom`。最低要求为 MoviePilot V3.2.12。

## 安装

在插件市场添加 `https://github.com/Azhz-Zhong/moviepilot-nodeseek-custom`，搜索「NS每日签到」并安装。

## 配置

- 填写登录邮箱和密码；同一个邮箱用于账号登录和邮件验证码。输入框留空表示保留已保存的信息。已有 Cookie 可在「高级设置」中导入。
- 如需浏览器验证服务，在插件中填写自己的服务地址。地址没有默认值，只保存到 MoviePilot 本机；服务需支持 `cf-clearance-scraper` 的 `waf-session` 和 `turnstile-min` 接口。
- 打开「使用 MoviePilot 系统代理」时，论坛请求和浏览器验证使用同一代理。服务连接本身走本机网络。
- 开启每日自动签到，设置北京时间。勾选「保存并立即签到一次」可以手动运行或核对已有记录。
- 结果通知使用 MoviePilot 的「站点」消息渠道。需要邮件验证码时会发送通知，即使普通结果通知关闭。

## 自动运行流程

1. 优先使用本机保存的 Cookie，先查询站点当天的签到记录；已签到直接记录实际收益，不再提交签到。
2. 当站点明确报告会话过期或要求登录时，使用已保存的账号密码登录一次。登录完成后保存新 Cookie，继续签到。
3. 登录要求邮箱验证时，尝试请求验证码邮件并通知用户，自动任务暂停登录尝试。
4. 在插件设置填入邮件验证码后保存，插件会提交验证码，成功后保存新 Cookie 并恢复签到。验证码错误时保留等待状态，可重新填写。
5. 等待验证码时，勾选「保存并立即签到一次」且不填写验证码可重新请求邮件。若邮件发送前的验证未成功，通知会提示在 NodeSeek 邮箱登录页面获取验证码。

账号启用额外的 2FA、服务故障或站点改变接口时，日志会提示对应原因。无法确认结果的签到请求不会自动重发；手动执行会先核对当天记录。

## 数据和隐私

Cookie、账号密码、绑定邮箱、验证码和私有服务地址不写入代码或执行日志。配置输入保存后清空，账号、会话和服务地址原子写入 MoviePilot 插件数据目录，限制为文件所有者访问。验证码仅暂存内存并在执行时消费。账号密码只发送到 NodeSeek，浏览器验证服务仅接收目标网址和代理配置。

详情页显示近 7 天实际鸡腿收益和最近 100 条执行日志，包括步骤、HTTP 状态、验证耗时、登录状态与结果。需要保留这些数据时，请备份 MoviePilot 配置目录。

## 开发和验证

- `package.v3.json`：插件市场索引。
- `plugins.v3/nodeseeksigncustom/`：插件、客户端和验证服务适配代码。
- `tests/`：使用合成凭据的离线测试，运行 `python -m unittest discover -s tests -v`。
- `har/`、`*.har`、会话文件和本机私有配置均被 Git 忽略。
- 卡片图标源自 NodeSeek 官网公开图标。

发布前同时检查 Git 暂存文件列表与内容。不要把部署脚本中的真实内网地址、Cookie、密码或 HAR 提交到仓库。
